# Видение дальнейшей доработки

Исторический монолитный референс уже давно перерастён. `proect1/` живёт как отдельный модульный продукт, поэтому дальнейший рефакторинг теперь должен быть направлен не на “разбить один файл на много”, а на качество UX, устойчивость пайплайнов и ясность кода.

## Уже сделано

- вкладки разделены по ответственности
- есть общий `FileListWidget`
- тяжёлые задачи работают через планировщик и очередь
- чат вынесен в отдельный `chat_client`
- добавлена диагностика среды
- добавлена поддержка больших текстов в чате
- убраны многие мусорные артефакты при URL-обработке

## Приоритеты следующего этапа

### 1. Единый слой уведомлений

Сейчас часть сообщений уже переведена с popup-окон на встроенные уведомления внутри приложения. Дальше это стоит довести до конца, чтобы:

- queue/status сообщения были единообразными
- важные ошибки были заметны, но не раздражали
- приложение ощущалось менее “техническим”

### 2. Унификация прогресса по вкладкам

Во всех тяжёлых пайплайнах желательно показывать:

- этап
- прогресс этапа
- итоговый статус
- длительность

### 3. Дальнейшая очистка хвостов

После активных итераций в проекте периодически появляются:

- дублирующиеся методы
- устаревшие комментарии
- старые popup-сценарии
- исторические текстовые документы с неверным описанием архитектуры

Нужна периодическая техническая ревизия.

### 4. Более умное планирование задач

Текущий планировщик уже защищает от конфликтов тяжёлых задач. Следующий шаг — различать:

- тяжёлые CPU/IO задачи
- лёгкие фоновые операции
- сетевые запросы чата

И разрешать больше безопасных комбинаций без риска подвесить UI.

### 5. Улучшение Chat UX

Следующий уровень для чата:

- мягкое отображение прогресса многошаговой обработки больших текстов
- явные метки режима `обычный ответ / саммари / конспект`
- опциональное сохранение отдельных сессий или экспорт markdown-диалога

## Главный принцип

Любое следующее изменение должно проверяться не только по “работает / не работает”, но и по трём вопросам:

1. Стало ли приложение понятнее пользователю?
2. Стало ли меньше скрытых конфликтов между подсистемами?
3. Стало ли проще поддерживать код без накопления новых хвостов?
