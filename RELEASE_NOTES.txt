🆕 WHAT'S NEW IN v1.0.6
================================================================================

1. FIXED: WINDOWS STARTUP CRASH "WinError 1114" (c10.dll)
   • On some Windows machines the app crashed at launch with
     "OSError: [WinError 1114] ... Error loading ... c10.dll"
   • Root cause: a PyTorch 2.9-2.14 regression (pytorch/pytorch#166628) -
     the DLL loader added in 2.9 fails inside PyInstaller builds where Qt
     DLLs are already loaded; torch 2.14.1+cpu was shipped in v1.0.5
   • Fix: the Windows build now pins torch to 2.8.0 (the last version
     without the faulty loader; the proper fix lands upstream in 2.15)

2. FRIENDLY STARTUP ERROR DIALOG INSTEAD OF A CRASH TRACEBACK
   • If PyTorch still fails to load (e.g. missing/old VC++ Redistributable
     on the user machine), the app now opens a clear dialog with actions:
     install Microsoft Visual C++ Redistributable (x64) / check Windows
     10-11 64-bit requirement / download the latest build - each opens the
     right page in the browser; technical details are under "Details"

3. BUILD HARDENING
   • UPX compression is disabled in the PyInstaller spec (documented
     PyInstaller trap: UPX corrupts torch/vcruntime DLLs on Windows and
     can cause the same "DLL initialization routine failed" error)

4. WEBSITE / ONBOARDING
   • Windows install steps now include a troubleshooting item for the
     DLL error with a direct link to VC++ Redistributable (x64), and the
     release page lists the same instructions

📝 VERSION: 1.0.7

✅ STATUS: Production Ready

================================================================================
🆕 WHAT'S NEW IN v1.0.7
================================================================================

1. FIXED: YOUTUBE "Requested format is not available" (PO TOKEN) IN THE
   PORTABLE BUILD
   • The EJS challenge solver needs a JavaScript runtime (deno); the pip
     "deno" package installs its binary into the venv scripts dir, which
     PyInstaller never collects - so the solver was dead in every portable
     build and YouTube skipped ALL media streams (PO Token protection)
   • Fix: the deno binary is now bundled into the app (next to the exe on
     Windows - exactly where yt-dlp looks first; on macOS in
     Contents/MacOS; on Linux in the app folder) for all four artifacts
   • The "Requested format is not available" hint text is updated to match
     the desktop app (no more "reinstall the engine" advice)

2. FIXED: WHISPER MODEL DOWNLOAD IN SETTINGS CRASHED INSTANTLY
   ("NoneType' object has no attribute 'write'")
   • Root cause: PyInstaller windowed builds have sys.stdout/stderr = None
     (documented behavior), and whisper's model downloader draws progress
     with tqdm, which writes to sys.stderr -> instant AttributeError
   • Fix: missing std streams are now replaced with /dev/null at startup
   • Model downloads are also more robust now: a direct-download fallback
     (requests, streaming, resume, SHA256 check, 3 retries) kicks in if the
     stock whisper downloader fails, with live progress in the status cell
   • Errors now show a human hint (VPN / network / retry) and the full
     tracebacks under "Details" instead of a bare one-liner

3. ONBOARDING: THE PROGRAM IS PORTABLE - NOW SAID OUT LOUD
   • Windows and Linux install steps now explicitly state the program is
     portable (nothing to install, everything lives in one folder), advise
     moving the extracted folder to a permanent location and always running
     it from there (and NOT to C:\Program Files); notes that settings and
     models live in the user profile, so moving the folder is safe
   • The release page lists the same instructions

4. CARRY-OVER FROM v1.0.6
   • torch pinned to 2.8.0 (PyTorch 2.9-2.14 WinError 1114 regression),
     UPX disabled, friendly startup dialog if PyTorch fails to load
